# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Development Commands

```bash
npm run dev        # http://localhost:4321 with hot reload
npm run build      # production build to dist/
npm start          # run dist/ reading .env
npm run check      # TypeScript type check
npm test           # unit tests (carousel, chatbot search and protections); test:demo / test:statuto run against the Docker image
npm run format     # Prettier (TS, CSS, MJS, JSON; .astro files are formatted by hand)
npm run icons      # regenerate Font Awesome icon subset (run after using a new fa-… icon)
```

`predev`, `prebuild`, `precheck` auto-run `npm run icons` — no need to run it manually before those.

No comments in code (TS, CSS, Astro, config): names and this file carry the explanations. Only functional directives stay (`/// <reference>`, `// @ts-check`).

## Standards for every change

Every new or edited line follows these rules; `npm run verifica:stile`, `npm run check`, `npm run format:check` and `npm test` must pass before committing.

- Minimal and current: no dead code, no unused files, assets or exports, no duplicated markup or CSS (reuse the components and shared classes below), no comments, Prettier formatting.
- Only essential files in the repo: no seed data, no generated output, no working material, no local tool settings (`.claude/` is ignored).
- Typography and colours only from the tokens (site, chat panel and dashboard alike). Every `<p>` is body text at `--body-size`.
- Accessibility (WCAG 2.2 AA, checked with axe-core at desktop and 390px width, zero violations): one `h1` per page, no skipped heading levels, real landmarks (no `aside` inside sections, no redundant roles), every control with a visible or accessible name, no interactive element inside `<summary>` or another control, decorative icons `aria-hidden`, text contrast ≥ 4.5:1 (state colours `--esito-*`), links with `target="_blank"` announce it (`<span class="sr-only"> (si apre in una nuova scheda)</span>` or in the `aria-label`), `.sr-only` from `base/accessibilita.css` for screen-reader-only text.
- SEO and GEO: unique title (≤ 60 chars) and description (≤ 160) per page, canonical, Open Graph with `og:image:alt`, `<Base tipo>` for the schema.org page type (WebPage, AboutPage, ContactPage, CollectionPage) linked to the school (`#scuola`) and site (`#sito`) entities defined on the home, BreadcrumbList (`#percorso`) from `<Breadcrumb>`, course and event data in `src/lib/schema.ts`. New public pages go in `src/data/navigazione.ts` (menu, breadcrumb, footer); the sitemap lists every page of `src/pages` and every course by itself. `/llms.txt` and the chatbot read the same official data (`src/lib/riepilogo.ts`). `src/pages/404.astro` is `noindex`.

## Architecture

**Astro 7** with hybrid rendering. Default output is `static` (prerendered HTML), but pages with `export const prerender = false` are SSR. Currently SSR: `/login`, `/dashboard`, `/presentazione` (+ the `/sito-oggi/*` proxy and `/presentazione/google`), `/robots.txt`, `/sitemap.xml`, `/llms.txt`, `/documenti`, `/spettacoli-eventi` (+ `/spettacoli-eventi/<slug>/calendario.ics`), and the image asset route. Server islands (`server:defer`, the page stays static): `Banner`, `RecensioniGoogle` (home), `OrariSegreteria` (`/contatti`).

### Request flow

```
Browser → Astro page / Action
```

Old site URLs (`/danza_classica_accademica.html` …) are redirected (301) by `src/pages/404.astro` (rendered on demand): names that changed are mapped, the others become the same name with hyphens. CSRF: Astro's built-in origin check (`security.checkOrigin`, on by default) rejects cross-site form posts; JSON Action calls are same-origin only (no CORS headers).

### Middleware (`src/middleware.ts`)

Runs on every on-demand request (pages rendered on demand, Actions, server islands, `/_image`, asset routes), never on prerendered pages:

- POST bodies over 256 KB (`Content-Length`) are refused with 413 before they are read; only the three upload Actions (`immagini.carica`, `documenti.salva`, `insegnanti.salva`) accept more, and only with a logged-in session.
- POSTs to `/_actions/*` need an `Origin` header equal to the site origin (403 otherwise), so scripts and tests calling an Action must send it.
- `/_image` (the Astro endpoint that resizes the photos of on-demand pages with sharp on every request) goes through `src/lib/immagini-ottimizzate.ts`: each variant is produced once and kept in memory (64 MB, least recently used out first, `immutable` + ETag); only the shapes the site generates are accepted (`href` in `/_astro/`, `w`/`h` up to 2560, `f` webp/jpg/png, `fit=cover`), at most 90 new variants a minute. Anything else, or a new variant over that ceiling, is redirected to the original file, so photos keep showing and nobody can make the server resize without end. A new `getImage` option (quality, another format…) must be added to `PARAMETRI` / `FORMATI` there.
- Every response gets `X-Content-Type-Options`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy`; `/login` and `/dashboard` are `no-store`.

Today's site is shown through the same-origin proxy `/sito-oggi/<path>` (`src/pages/sito-oggi/[...percorso].ts`: only for a logged-in session, only `SITO_ATTUALE`'s host, `<base href="/sito-oggi/">` injected into HTML, `noindex`, `Disallow`), so old and new site are highlighted the same way: `evidenzia` is a CSS selector whose visible matches are joined into one box (`#clients01-7m, #footer1-6i`), each one shrunk once to what is actually drawn inside it (text, images, controls, elements with a background, border or shadow; `contenuto()`), so the spotlight hugs the content pixel for pixel (no margin, 4px ring outside, small radius), `frase: [from, to]` narrows it to a stretch of text inside the first match, `fermo` leaves the page at the top (the phone title hidden under the menu); the page is scrolled by the script, never by anchors, so the element sits in the free area under the fixed header (`FISSI`, including the old `.navbar-fixed-top`) and above the navigation, with bottom padding added when the page cannot scroll far enough. A box as wide as the page becomes a full-width band. Speed: each screen keeps a pool of up to four iframes (`cornici`, one per address, least recently used out) and, 300 ms after every step, the next two steps and the previous one are loaded hidden in the pool, so arriving on a step usually shows a page already loaded and the spotlight appears at once. A frame still loading stays hidden on a dark background until `load`, then the element is placed, placed again after `ASSESTAMENTO` (250 ms) and only then frame, spotlight and note appear together (15 s at most, `ATTESA_MASSIMA`). The `/sito-oggi` proxy keeps each file in memory for an hour (60 MB at most, one fetch shared by concurrent requests) and injects a style that switches off the old site's animations and transitions, so its pages are final as soon as they load. Changing step fades (`pres-dissolvi`, only with `prefers-reduced-motion: no-preference`). Spotlight: the rest of the page under an 82% dark layer, a light-blue border with a breathing glow, no label; it disappears as soon as the visitor clicks or scrolls in the site (window `blur` with the iframe focused, `wheel` / `touchmove` on the framed document; on external pages a transparent layer `data-tocco` takes the first click or wheel). Arrows and the keyboard never get stuck: keys pressed inside a same-origin frame are forwarded to the slides (unless typed in a field), and every 250 ms (`CONTROLLO_FOCUS`) the stage takes the focus back if a cross-origin frame grabbed it (Google's consent dialog focuses itself); the site fills the whole window, so the pointer is always over it and cannot be used to tell. Orari segreteria and recensioni highlight their whole block (`.info-blocco:has(orari-segreteria)`, `.recensioni-layout`); a renamed class or id on either site needs the step updated (the dashboard steps find their element only when it has data). Desktop screens are rendered at the real width of the screen area (1:1), scaled down only below 1280px. Phones are 390×844 inside a realistic mockup (`presentazione/telefono-realistico.webp`, `TELEFONO_SOPRA` / `TELEFONO_SOTTO`), as large as the window allows and centred horizontally and vertically on the whole stage (two phones side by side, close together), even if the note and the navigation cover part of them. ### Backend: Astro Actions

All backend logic lives in `src/actions/index.ts` — no separate API routes. Actions are grouped: `chatbot`, `eventi`, `tipi`, `immagini`, `documenti`, `insegnanti`, `demo`, `auth`. Admin actions guard themselves with `soloAdmin()` (checks session). Called from the browser via `import { actions } from 'astro:actions'` or as `<form>` action.

### Data layer

Everything is JSON files on disk in `DATA_DIR` (default `./data/`, set in `.env`). The `src/lib/storage.ts` module provides:
- `readJson` / `writeJson` (atomic: write temp file → rename). `readJson` returns the fallback only when the file does not exist; any other read error is thrown, so a temporary disk error can never make a save overwrite real data with an empty list; a file that is not valid JSON is renamed `<name>.illeggibile` (kept for recovery) and the fallback is used
- `serviFile` streams uploads (ETag, 304, `Content-Length`), never loading the file in memory
- `serialized()` — a promise queue that prevents concurrent read→modify→write races

File layout in `data/`:
- `eventi.json`, `tipi_evento.json` — event data (created on first save; the repo ships no data)
- `analytics.json` — chatbot logs (capped at 10000 entries)
- `sessions/` — fsLite session driver
- `uploads/eventi/` — event posters: uploads are resized (1600px) and converted to WebP, plus a `<name>.mini.webp` thumbnail for the dashboard library
- `documenti.json` — texts and PDF list of `/documenti` (defaults in `src/data/documenti.ts` until first save)
- `uploads/documenti/` — PDFs uploaded from the dashboard, served on `/assets/documenti/<file>`
- `insegnanti.json` — header and teacher cards (name, role, bio, competenze list, photo) of the «Insegnanti» carousel in `/chi-siamo` (dashboard › Insegnanti; defaults in `src/data/insegnanti.ts`, no teachers by default: the section is hidden while the list is empty). `/chi-siamo` is therefore rendered on demand. Demo teachers (dashboard › Insegnanti › Dati demo, `generaInsegnanti` in `src/lib/demo.ts`) carry `demo: true` and are removed with their photos in one click; their portraits come from `demo/insegnanti` (vertical photos named `donna-*` / `uomo-*`, the prefix picks the name), without photos they get initials
- `uploads/insegnanti/` — teacher photos, cropped 4:5 (800x1000) and converted to WebP on upload, served on `/assets/images/insegnanti/<file>`
- `conversazioni/` — chatbot conversations, one `<uuid>.json` per chat (deleted after 30 days)
- `google.json` — Google Places cache (rating, review count, 5 latest reviews, opening hours), see Google below
- `ricerca-google.html`, `ricerca-google.json` — Google's real results page for the presentation and its date (SerpApi, refreshed once a month)

In Docker, this directory is a named volume (`inballet-data`) so data survives rebuilds.

### Events

`src/lib/eventi.ts` is the single source: the zod schema `inputEvento` (used as the `eventi.salva` Action input; the dashboard shows its per-field errors), read/write, time rules and presentation helpers.

- Model: `data`/`ora` start and `dataFine`/`oraFine` end, all mandatory (`inputEvento` rejects an end missing or not after the start; the dashboard asks for the date, start and end time (the «Luogo», «Per chi» and «Costo» suggestions from past events come from a `datalist` whose arrow is hidden), and the end date only when «Finisce in un altro giorno» is ticked, otherwise it sends the same date and a same-day end is stored with an empty `dataFine`; demo events have both), `stato` (`pubblicato`, `bozza` = hidden from the site, `annullato`, `esaurito`), `prenotazione` link, `slug` (+ `alias` of old slugs).
- No per-event pages on purpose: the `/spettacoli-eventi` section has no visible header (only an `sr-only` h2) and opens on the month calendar (month name centred between the two arrows), with the «Calendario / Elenco» switch above it (the SSR list stays as the view without JavaScript, `@media (scripting: none)`); details open in a modal (SSR list + `scripts/calendario.ts`), same structure at every width: the sticky top bar holds «Condividi» as an icon-only `btn-icon` (the label is `sr-only`; the icon turns into a check for 2.5s when the link is copied) next to the close X, both white with a soft shadow in this modal because they sit on the light-blue header; a `--bg-soft` header (`.evento-testata`, flipped site wave `--onda-svg` as its bottom edge) with type/state labels, title and description; the poster as a white-bordered «polaroid» rotated 3° (straightens on hover, opens whole and enlarged on click; it sits on a blurred copy of itself, `contain`); then Quando / Dove / Per chi / Costo (label above value, two columns above 600px with a 3rem gap and a grey `--linea` vertical rule centred in it beside every right-hand cell, stopping 1rem short of the horizontal rules; one column below) and «Aggiungi al calendario» (Google and Apple brand icons on the two pills) / «Prenota». Desktop (>900px, 52rem with a poster, 48rem without): the 10rem poster sits on the right inside the header, vertically centred on labels, title and description (same top and bottom offsets as the header text), so it no longer crosses the wave; tablet and mobile: the poster is centred under the header, straddling the wavy edge. Demo posters are always vertical. `?evento=<slug>` (or an old slug / the id) opens the modal and sets og:title/og:image to that event, so shared links preview the poster. The page also carries schema.org/Event JSON-LD for upcoming non-demo events (`datiStrutturati()`).
- Text fields are stored as plain text and escaped when rendered.
- One rule for "past" everywhere (site, banner, dashboard, chatbot): `passato()` = `fineEvento()` is over, Rome time: an event ending at 12:10 is «Evento concluso» from 12:10:01, whatever its start. Between `inizioEvento()` and the end `inCorso()` is true: «In corso» on the cards, the modal and the dashboard. Events saved before the end became mandatory fall back to the start time (23:59 without any time) until they are edited.
- Event banner (`Banner.astro`, server island, `no-store`): the not-past events ordered by `fineEvento()`, so each one gets its turn before it ends; it stays up until the end (from the start its date reads «In corso • fino a …») and the page switches to the next one at the exact second (timer, re-checked on `visibilitychange` / `pageshow`). It receives the 10 events ending first plus every other event on their days, so a day group is always complete. When other shown events start on the same day as the current one, the banner shows them together: «N eventi in programma», «<day> • dalle <first start>» (or «in corso» once one has started), and «Scopri di più» opens `/spettacoli-eventi`, not a single event. Closing it (or «Scopri di più») hides only that event, or every event of that day group (`banner_dismissed_<id>` in localStorage): the next event shows again to everyone.
- Demo posters (`creaLocandina` in `src/lib/demo.ts`) are always vertical, 1080×1350 (4:5).
- Removing a type keeps it on the events that use it; deleting a poster clears it from the events that use it.

### Google (reviews and opening hours)

`src/lib/google.ts` is the only place that talks to Google: one Places API (New) Place Details call (`rating,userRatingCount,reviews,regularOpeningHours`, billed once as Enterprise + Atmosphere) every 30 days, from the server with `GOOGLE_PLACES_API_KEY`, saved in `data/google.json`. Every visitor sees that file; nothing Google runs in the browser (no Maps JS, no client key). An expired file is still served while the refresh runs in the background; a failed refresh is retried after 1, 2, 4… hours (24 at most), and an answer without reviews or without opening hours is refreshed after a day instead of 30, so Google is called at most about once a day in the worst case. Concurrent visitors share one read of the file and one call; a `google.json` with the wrong shape is ignored. No hand-written fallback: the opening hours exist only on Google (Google Business Profile is the place to change them, the site follows within 30 days or at once if `google.json` is deleted).

- Home «Dicono di noi»: `<RecensioniGoogle server:defer>` (static page, the island is rendered on demand, `Cache-Control` 1h); `scripts/recensioni.ts` (`<recensioni-google>` custom element) only drives the carousel and «Leggi tutto».
- `/contatti` «Orari segreteria»: `<OrariSegreteria server:defer>` with the week and the openingHoursSpecification JSON-LD of `#scuola`; `scripts/orari.ts` (`<orari-segreteria>`) marks today and «Aperto/Chiuso ora» in the visitor's browser (Rome time).
- The same data feed `riepilogoScuola()` (opening hours and rating for `/llms.txt` and the chatbot).

### Chatbot (Étoile)

`src/lib/chatbot/`, one file per concern; `index.ts` (`rispondi()`) runs the flow: sanitize → in-memory rate limit per IP hash (1s, 6/min, 30/h, 100/day; 60 attempts/h block the IP for an hour, and a blocked IP is no longer logged; IPv6 addresses count by /64 network, `reteDi()`) → insult/spam filter → site-wide ceilings (`tetto` in `protezioni.ts`, whatever the IP: 60 messages/min, 600/h, 3000/day, then a «riprova tra qualche minuto» answer without reading or writing anything; 300 refused messages logged per hour, so a flood cannot push the real history out of `analytics.json`) → conversation memory (last 6 exchanges, max 20 per chat) → response cache (first message of a chat only, in memory, 24h, key includes the knowledge version) → daily spend cap → model ceilings (20 calls/min, 200/h, 1000/day and 6 at the same time, then FAQ answers: with the spend cap this bounds the bill even if every request comes from a different address) → provider chain → FAQ fallback → log + save exchange.

- `fornitori.ts`: provider chain from `CHATBOT_MODELLI` (`fornitore:modello,...`, in priority order). Two adapters: official `@anthropic-ai/sdk` for Claude, OpenAI-compatible chat completions for gemini/mistral/groq/openrouter/openai/cerebras/`compatibile` (any URL in `CHATBOT_COMPATIBILE_URL`). Providers without a key are skipped. Hedged requests: a provider that fails hands over at once, one still silent after 5s gets the next one started in parallel, first valid answer wins and the others are aborted (the beaten one counts an error). Per-provider timeout 12s; 502/503/529 retried once at the end of the queue; circuit breaker (3 errors or slow losses → 5 min pause, 429 → `retry-after`, 4xx config errors → 30 min). No streaming (speed is bound by the provider queue).
- Opening the chat calls `actions.chatbot.prepara` (crawl + index build), so the first question doesn't wait for it. Crawl and index build are shared by concurrent requests; a failed or half-empty crawl (under half of the pages read before, or over 45 s) keeps the previous texts and is retried after a minute.
- `conoscenza.ts`: about 4k input tokens per question instead of the whole site (~21k, which hit the Gemini free-tier tokens-per-minute limit after ~10 questions a minute). System prompt, cached by the providers (Claude: 1h on the fixed part): fixed part = instructions + official data (`riepilogoScuola({ conFaq: false })`, shared with `/llms.txt`) + index of the site pages (path: title); variable part = date, documents, next 10 events (rebuilt every 5 min). Then `contesto()` adds to the last user message only the passages relevant to that question («PASSAGGI DEL SITO»), chosen among page sections, every FAQ and the next 30 events (demo ones included because the site shows them). Follow-ups ("e da che età?") search with the previous questions too and favour the pages cited in the last answer.
- `ricerca.ts`: local BM25 search, no external service, no vector DB: Italian normalisation (accents, light stemming incl. verbs), stop words, `SINONIMI` in `src/data/chatbot.ts` (replacements applied before stop words: «bimba» → bambina bambini, «dove» → sede indirizzo…), ages indexed by range («da 6 a 8 anni» answers «7 anni»), section titles and page path weighted double, max 6 passages / 5500 characters / 3 per page. `dividi()` cuts a page at its `##` headings (max 1200 characters, short sections merged). Covered by `tests/ricerca.test.mjs`.
- `pagine.ts`: the server crawls its own site (from `/`, following internal links, max 150 pages; first `localhost:$PORT`, then the request origin) and keeps the `<main>` text of each page, dropping lines repeated on many pages and every `section[data-chatbot-escludi]` (event calendar, «Corsi simili», gallery, contact CTA, home FAQ: already indexed from the data). Re-read every 30 min in production (1 min in dev) in the background. Any new page linked from the site is covered automatically; text outside `<main>` (navbar, footer) and server islands are not, contacts and opening hours come from the official data.
- `offline.ts`: when no provider answers or the spend cap is hit, the best `faq` match from the same search (at least 2 words of the question in common) plus the course page if a course is named, or upcoming events. The bot always answers.
- `registro.ts`: `analytics.json` entries with provider, tokens, cost (`PREZZI` in `src/data/chatbot.ts`), latency, fallbacks; written in batches (one write every 2s at most, capped at `MAX_LOG`). For the daily spend cap a model missing from `PREZZI` counts at the most expensive listed price (it used to count zero, which switched the cap off): add new models to `PREZZI`.
- `formato.ts`: escape everything, then rebuild bold/lists/links; links only to site paths, tel/mailto and a few known hosts.
- Dashboard (Chatbot tab): spend, provider chain status, quality check (`VERIFICHE` in `src/data/chatbot.ts`, run per provider via `actions.chatbot.verifica`), last conversations.

All server env vars are `access: 'secret'` on purpose: read at runtime, so they can change without a rebuild. The schema with defaults is `env.schema` in astro.config.mjs; values go in `.env` (no quotes):

### UI system (use it, don't invent new styles)

### CSS structure (`src/styles/`)

No `<style>` blocks and no `style=` with real properties in `.astro` files: all CSS lives in `src/styles/`, and the file that uses it imports it in its frontmatter (`import '../styles/pages/chi-siamo.css'`), so each page loads only its own CSS. Plain CSS (no scoping): class names must be unique across files, prefix them with the page or component.

```
styles/
  global.css        only an ordered @import list of the shared modules (imported by layouts/Base.astro)
  base/             variables.css (ALL tokens: palette, type scale, radii, shadows, motion, header and wave sizes,
                    decorative image paths) · reset.css (reset, html/body, focus, skip link) · typography.css
  layout/           container, intro-editoriale, decori (decoro-onde + veils), onde (wavy edges)
  components/       shared by several pages: buttons, citazione, voci, foto-cornice, carosello, hero, sfondo,
                    breadcrumb, cta-contatto, intro-split · one file per component with its own markup
                    (navbar incl. the fixed header, footer, banner, chatbot, galleria, insegnanti-*, corsi-simili, …)
  pages/            one file per page, imported by the page; only layout (grid, spacing, alignment), never its own
                    label/title/button typography or colours
  admin/            dashboard and login (own tokens in admin/variables.css, not loaded by the public site)
  icons.css         generated by `npm run icons` (gitignored)
```

New values (colours, sizes, shadows) go in `base/variables.css`; a rule needed by two or more pages goes in `components/` or `layout/`, not copied. `npm run verifica:stile` enforces this.

Shared classes and tokens: every content section uses them.

- Section header: `<span class="eyebrow">` → `<h2 class="titolo-sezione">` (optional `<em>` for the light italic accent) → `<p class="intro-sezione">`
- Dark or photo-background section: add `sezione-scura` on the `<section>` (eyebrow, title and intro switch to light colors)
- Buttons: `btn-primary` (blue pill), `btn-secondary` (white outline, on photos/dark); text action link: `link-cta`; round icon buttons `btn-icon` (see Type scale and single style system)
- Tokens: `--section-y` (section vertical padding), `--bg-soft` (alternate section background), `--radius-card` / `--shadow-card` (cards), `--radius-img` (photos, with the offset blue frame used in Contatti/Corsi/homepage story)
- Page hero: `<HeroPagina titolo stile [corso]>` (src/components/HeroPagina.astro; photo from `heroPagina()` in src/lib/hero-pagine.ts, course pages use `heroDa()`; the page passes `preload={hero.preload}` to `<Base>`, which writes the image preload links): photo, bottom gradient, breadcrumb, h1, then the slot (`<p class="hero-lead">`, extra buttons). Text left-aligned and vertically centered. No glass panels.
- Navigation data lives in `src/data/navigazione.ts`: the navbar (desktop + mobile, active page highlight) and the breadcrumbs (+ BreadcrumbList JSON-LD) are generated from it. Add new pages there; pages outside the menu go in `altrePagine`.
- Intro section of an inner page: add `intro-editoriale` to the wrapper (eyebrow, title and text stacked, never text to the right of the title; centered on desktop, left-aligned at ≤900px; a `*-highlight` quote becomes a blue rule)
- Header + list sections: the owner chooses case by case (the six pages with an intro «text + photo» and a «header + list» section share `components/intro-split.css`: `intro-split-*`, `split-section` / `split-layout` / `split-header` [+ `--sticky`, `--soft`]). Side by side (header left, sticky if long, list right; stacked at ≤900px) in homepage Formazione/Dicono di noi/FAQ, Collaborazioni progetti, Sportello accesso, Classi integrate, NoiConVoi destinatari, Sostenitori destinazioni, Formazione insegnanti aree. Stacked (`intro-editoriale` above, content below in a centered `max-width: 48rem` column) elsewhere, e.g. Chi siamo numeri, Diploma, Dona. Ask before switching one to the other.
- Lists of points (pillars, values, timeline…): `<ul class="voci-griglia">` (3 columns, one at ≤900px) of `voce` / `voce-icona` / `voce-anno` / `voce-titolo` / `voce-testo` (columns with a blue top rule). No cards with icons in colored circles.
- Photo zoom: `components/zoom-foto.css` is shared by the event poster and the teacher photo: `.zoom-icona` (round expand badge on the clickable image) and `.zoom-dialog` (full-screen dark dialog with the whole image, `.zoom-chiudi` X, any click closes it, Escape closes only the zoom). The teacher card wraps its photo in `.ins-dialog-foto-btn` (`data-zoom-foto`), opening `#insegnanteFoto` (rendered once, only when some teacher has a photo).
- Content dialogs (event detail, teacher card): `<dialog class="dialogo …">` with `dialogo-barra` (sticky close button) and `dialogo-corpo` (`components/dialogo.css`, zero-specificity base: page CSS adds only what differs). Full screen at ≤600px. Dialogs are clipped with `clip-path: inset(0 round var(--radius-card))` (none when full screen), so the scrollbar never squares the right corners (a clipped dialog has no outer shadow; the backdrop sets it apart); the event modal also hides its scrollbar (`scrollbar-width: none`, wheel and touch still scroll) so no white strip runs beside its light-blue header. Every public `<dialog>` has `tabindex="-1"` and its script calls `.focus()` on it right after `showModal()`, so opening it never lights the focus ring on its first button (browsers ignore `autofocus` on the dialog itself); the ring appears only once the visitor presses Tab (`dialog[tabindex]:focus-visible` has no outline in `base/reset.css`).
- CTA section before the footer: `<CtaContatto stile={…}>` (src/components/CtaContatto.astro, CSS in `components/cta-contatto.css`) with the `h2.titolo-sezione` and `p.intro-sezione` in the slot; the «Contattaci» button is fixed. Background from `sfondoCta(tema)` in `src/lib/images.ts` (`cta/<tema>-desktop|tablet|mobile.webp`); on course pages the theme is `ctaTema` in `corsi.json`. Breakpoints: desktop >900px, tablet 601-900px, mobile ≤600px. Measured section sizes (cover-cropped, dark overlay on top): desktop 1015-1910 × 356-433, tablet 591-890 × 307-387, mobile 360-590 × 307-462. Source files to supply: desktop 2560×640, tablet 1600×800, mobile 1200×1400 px; keep the subject inside the central safe zone (desktop 50% width / 70% height, tablet 70% / 80%, mobile 80% / 55%).
- Decorative waves (desktop >1024px only, faded, covering the whole section): add `decoro-onde` or `decoro-onde decoro-onde--sinistra` (mirrored) on a white `<section>` only, never on a `bg-soft` (azzurrino) or dark one. The event modal (`dialog.evento-dialog`) carries `decoro-onde` too (`:is(section, dialog)` in `layout/decori.css`; never `background-attachment: local` on a dialog, it leaves the scrollbar gutter without background and the right corners look cut): they show in its white part, below the light-blue header. The chat panel of Étoile carries the same waves as the background of the conversation area (`#cb-msgs`, at every width, over `--grigio-50`; the bubbles keep their own backgrounds). Images `src/assets/images/decorazioni/onde-destra.webp` / `onde-sinistra.webp` (mirrored), already faded to 22% in the file, set as section `background-image` via the `--decoro-onde*` variables in `base/variables.css` (rules in `layout/decori.css`). Every white section gets it (the owner wants it on all of them), alternating right and `--sinistra` when two white sections are close, so a new white section must carry `decoro-onde` too.
- Section edges: no accent lines or borders at the top/bottom of a section. Sections are told apart only by alternating background (white / `--bg-soft`); never put two sections with the same background next to each other (the footer and `sezione-scura` blocks are dark). Hairlines (`rgba(26,26,26,.12)`) are only for rows inside a section.
- Wavy section edges: every `main > section` after the first and the footer get a small decorative wave on their top edge (`layout/onde.css`, `--onda-h` / `--onda-w` in `base/variables.css`): transparent `border-top` + negative `margin-top` + `mask`, so layout doesn't change and the previous section shows through. Don't set your own `border-top`/`margin-top` on top-level sections. Sections whose background photo is a child element named `*-bg` / `*-overlay` are extended into the wave band automatically; for a new kind of background child, give it `top: calc(var(--onda-h) * -1)` and `height: calc(100% + var(--onda-h))`, and avoid `overflow: hidden` on the section. Each section also gets a transparent `border-bottom: var(--onda-h)` so the wave of the next one does not eat its bottom padding (the hero has it in its padding instead).
- Style: editorial, not template-like. No gradient icon tiles, no floating badges over photos, no invented metrics.
- Bold (`<strong>`) in body text: 1-3 key words or short phrases per paragraph (ages, qualifications, course and project names, the action to take), never whole sentences, never trailing punctuation inside the tag, never inside links or headings. Styled globally in `global.css` (`main strong`: 600, dark; white on dark sections and heroes). Where text lives in data used elsewhere (chatbot, schema.org, llms.txt) keep it plain and list the phrases in `evidenzia` (see `faq` and `categorieCorsi` in `src/data/scuola.ts`), rendered with `enfatizza()` from `src/lib/text.ts`; course pages (`src/data/corsi.json`) carry `<strong>` directly. Texts edited from the dashboard use `**word**` (`grassettoDaTesto()`).

## Type scale and single style system
One system, all in `src/styles/` (tokens in `base/variables.css`, headings and text in `base/typography.css`); pages and components only lay things out. Run `npm run verifica:stile` before pushing: it fails on a `<style>` block in an `.astro` file, a literal `font-size` / `font-weight`, a hand-written colour, an inline style with real properties, or a heading restyled outside `base/typography.css`.

- **Roles, not sizes**: pages never pick a size, weight, line-height or colour for text. `base/variables.css` ("Ruoli tipografici") defines each role and `base/typography.css` applies it: titles `--h1-*` … `--h4-*` (h1 56px, h2 46, h3 32, h4 26 on desktop; one style per level on every page), body text `--body-*` (22px, 1.7, one colour for every paragraph/list), small text `--small-*` (`<small class="testo-piccolo">`: ages, frequencies, file sizes, sources; never on a `<p>`), hero lead (`.hero-lead`: body size, light weight), label `--label-*` (`.eyebrow`/`.titoletto`), buttons/links `--ui-*`, numbers `--numero-*`. Changing a role in the variables file changes the whole site. The raw scale `--text-5xl` … `--text-2xs` feeds the roles and sizes icons/numerals. **Every `<p>` is body text at `--body-size` (22px desktop, fluid down to 18px)**, on the site, in the chat panel and in the dashboard; anything smaller is not a paragraph (`<small>`, labels, UI). Dashboard/login (`admin/`, which imports `base/variables.css`) and the chat panel use the same palette, font and raw scale, never their own sizes or hex colours.
- **Tags carry the role**: titles are `h1`-`h4` (card/course/document/sede names `h3`, titles under an `h3` `h4`), text is `<p>` (or `li`, `dd`…), labels `<p class="eyebrow">`. Never a `<span>`/`<div>` for a title or a paragraph: `span` only for an inline fragment inside text (e.g. `sede-tag`, a count-up number) or an icon wrapper inside a button. Don't wrap button/link labels in a span; the visual «Scopri il corso →» label inside a whole-card link is `<span class="link-cta">`, timeline years are `<span class="voce-anno numero-medio">`, fine print (copyright, captions, notes) is `<small>`. `h2`/`.titolo-sezione` section title, dialog `h2` uses the `h3` style, `.valore` = `h4` style on a non-title (phone, email). Components never set size/weight/line-height/letter-spacing/colour on titles or paragraphs; big numbers `.numero-grande` / `.numero-medio`.
- **Labels**: one uppercase label style, `.titoletto` (and `.eyebrow`, same look plus margin): menu group titles, categories, table headers, footer column titles, any h2/h3 that is only a label.
- **Hero lead** under the h1: `.hero-lead` (home and inner pages), body size on desktop and `--lead-size-mobile` (16px) at ≤768px.
- **Buttons**: `.btn-primary`, `.btn-secondary`, `.link-cta`; round icon buttons `.btn-icon` + `--chiudi` (the close X of every dialog, site and lightbox: light grey circle `--grigio-100`, black X, `--grigio-300` on hover; the dashboard `.modal-close` matches it), `--scuro` (on photos/dark), `--contorno` (carousel arrows), `--nudo` (menu). 44px, same icon size. The navbar "Contattaci" is a `btn-primary` (`aria-current="page"` turns it white).
- **Motion**: durations and easing only from the tokens `--durata-breve` (hover colours), `--durata` (small movements, dialogs, dropdowns), `--durata-pannello` (mobile drawer), `--durata-lenta` (hero video fade), `--curva`. Animate only `transform` and `opacity` (colours on hover); layout properties are animated only for the scroll-shrinking header, the accordions (the mobile footer columns in `scripts/footer.ts` with the Web Animations API on the `<details>` height, `--durata-pannello`, so they open and close smoothly in every browser) and the width of the review dots (old and new pill change together, so the row keeps its width). The only load animation is the hero text rising in (`sale`, children of `.hero-content` / `.chisiamo-hero-glass` with an 80 ms cascade), starting from opacity 0.001 so the text still counts for LCP at first paint. Infinite animations only where they say something and only while visible: the light streak running along the Chi siamo timeline (`timeline-scia` on the desktop serpentine, `timeline-flusso` on the mobile line, the rings breathing around the «Oggi» dot and the «Dove trovarci» map pins and the streak running along the pin-to-photo lines (shared keyframes `respiro` with `--respiro-da` / `--respiro-a` and `scia` with `--scia` in `components/movimento.css`), and the second blob breathing around the «Cosa impareranno» icons, `impara-respiro`; both run only under the `in-vista` class that `scripts/in-vista.ts` toggles on every `[data-in-vista]` element); the event banner pulse runs 3 times. `prefers-reduced-motion` is handled once in `base/reset.css`; scripts check it only for JS-driven motion (carousels, counters, hero video). Carousels run their frame loop only while visible; the hero video starts after `load`. Scroll motion is CSS only (`components/movimento.css`, `animation-timeline: view()`, inside `prefers-reduced-motion: no-preference` and `@supports`, longhand properties because the minifier would fold `animation-timeline` into an invalid shorthand): section headers and list items rise in (`rivela`, `--rivela-y`) with a per-column cascade, framed photos enter with `scena`, the ondine drift with the scroll (`ondina-flusso` in `components/ondina.css`, the only paint-based motion). Never on the first section (hero) and inactive inside horizontal scrollers. Micro-interactions: arrows in buttons and `link-cta` move on hover, buttons press in (`:active`), course card photos zoom slowly, the home figures lift on hover.
- **Icons** follow the text next to them or a scale step: `--icona-in-testo`, `--icona-mini`, `--icona-punto`, never px/rem in components.
- **Rounded lines and cards**: no square line ends or corners anywhere. A CSS `border` always has square ends, so separators are never `border-top/bottom/left/right`: they are drawn by `components/linee.css` as 2px (`--linea-sp`) lines with round caps, using the element's own background (`--lc: <colour>; background: var(--linea-basso)`, also `--linea-alto` / `--linea-sx` / `--linea-dx`, several separated by a comma; set `--ls` for a thicker bar; on an element that also needs a background colour, put `background-color` after). The «+» of accordions is `background: var(--piu)` (`--ps` = size). Pseudo-element lines (`::before` / `::after`) get `border-radius: var(--radius-pill)`; short rules between groups are the double wave `components/ondina.css`. Boxes (cards, grids of cells, dialogs) always have `border-radius: var(--radius-card)` (or `--radius-md` for small ones); a grid of cells separated by a 1px `gap` on a coloured background is not allowed, use separate rounded cards with a gap or lines on the cells. Full-screen mobile dialogs and the mobile menu drawer are the only square boxes.
- **Colours** only from the palette tokens: `--white`, `--dark-navy`, `--primary-blue*`, `--text-*`, greys `--grigio-*`, states `--esito-*`, lines: ONE hairline colour `--linea` for every separator on light backgrounds (same as the home accordion; never invent another), `--linea-su-scuro` on dark, text on dark `--testo-su-scuro*`, and for transparencies `rgb(var(--navy-rgb) / .4)` (also `--bianco-rgb`, `--nero-rgb`, `--scuro-rgb`, `--blu-rgb`, `--blu-scuro-rgb`, `--header-rgb`).
- **Font weights** only from the tokens `--font-light` … `--font-bold` (300-700) or the role tokens (`--heading-weight`, `--ui-weight`…). Text colours from the role tokens (`--body-color`, `--small-color`, `--heading-color`, `--label-color`, and the `*-su-scuro` variants for dark sections) or `--text-body` / `--text-muted`.
- **Inline `style=`** is left only for the image data computed at build time, as CSS variables (`--sfondo-*` / `--fuoco-*` from `sfondo()` and `<Img fuoco>`); the rules that use them are in `components/sfondo.css`. Counters and per-item tweaks (index, number of items, logo scale, veil) are CSS: `:nth-child`, `:has()`, modifier classes or data attributes. The few `element.style` writes in `src/scripts` are runtime values (measured heights, drag offset, carousel slide state).

## Corsi simili
Every course page (`[corso].astro`) shows `src/components/CorsiSimili.astro` right after "Gli obiettivi": the other courses of the same `categorieCorsi` entry (scuola.ts), current course excluded; age label and frequency come from the course's own data in corsi.json. Desktop: at most 3 cards per row (6-column grid, cards span 2, an incomplete last row is centred); tablet 2 per row; mobile the shared photo cards. A new course only needs to be listed in a category to appear there.
