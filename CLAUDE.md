# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Development Commands

```bash
npm run dev        # http://localhost:4321 with hot reload
npm run build      # production build to dist/
npm start          # run dist/ reading .env
npm run check      # TypeScript type check
npm test           # unit tests (carousel, chatbot search and protections, Google cache, admin rich text, developer area source mapping); test:demo / test:statuto run against the Docker image
npm run format     # Prettier (TS, CSS, MJS, JSON; .astro files are formatted by hand)
npm run icons      # generate the custom InBallet SVG icon set
```

`predev`, `prebuild`, `precheck` auto-run `npm run icons` — no need to run it manually before those.

No comments in code (TS, CSS, Astro, config): names and this file carry the explanations. Only functional directives stay (`/// <reference>`, `// @ts-check`).

## Standards for every change

Every new or edited line follows these rules; `npm run verifica:stile`, `npm run check`, `npm run format:check` and `npm test` must pass before committing.

- Minimal and current: no dead code, no unused files, assets or exports, no duplicated markup or CSS (reuse the components and shared classes below), no comments, Prettier formatting.
- Only essential files in the repo: no seed data, no generated output, no working material, no local tool settings (`.claude/` is ignored).
- Typography and colours only from the tokens (site, chat panel and dashboard alike). Every `<p>` is body text at `--body-size`.
- Accessibility (WCAG 2.2 AA, checked with axe-core at desktop and 390px width, zero violations): one `h1` per page, no skipped heading levels, real landmarks (no `aside` inside sections, no redundant roles), every control with a visible or accessible name, no interactive element inside `<summary>` or another control, decorative icons `aria-hidden`, text contrast ≥ 4.5:1 (state colours `--esito-*`), links with `target="_blank"` announce it (`<span class="sr-only"> (si apre in una nuova scheda)</span>` or in the `aria-label`), `.sr-only` from `base/accessibilita.css` for screen-reader-only text.
- SEO and GEO: unique title (≤ 60 chars) and description (≤ 160) per page, canonical, Open Graph with `og:image:alt`, `<Base tipo>` for the schema.org page type (WebPage, AboutPage, ContactPage, CollectionPage) linked to the school (`#scuola`) and site (`#sito`) entities defined on the home, BreadcrumbList (`#percorso`) from `<Breadcrumb>`, course and event data in `src/lib/schema.ts`. New public pages go in `src/data/navigazione.ts` (menu, breadcrumb, footer); the sitemap lists every page of `src/pages` and every course by itself. `/llms.txt` and the chatbot read the same official data (`src/lib/riepilogo.ts`). `src/pages/404.astro` is `noindex`.

## Architecture

**Astro 7** with hybrid rendering. Default output is `static` (prerendered HTML), but pages with `export const prerender = false` are SSR. Currently SSR: `/privacy` (it lists the AI providers configured at runtime), `/login`, `/dashboard`, `/area-sviluppatori` (+ `/area-sviluppatori/file`), `/presentazione` (+ the `/sito-oggi/*` proxy and `/presentazione/chatgpt` / `/presentazione/claude`), `/robots.txt`, `/sitemap.xml`, `/llms.txt`, `/documenti`, `/spettacoli-eventi` (+ `/spettacoli-eventi/<slug>/calendario.ics`), and the image asset route. Server islands (`server:defer`, the page stays static): `Banner`, `RecensioniGoogle` (home), `OrariSegreteria` (`/contatti`).

### Request flow

```
Browser → Astro page / Action
```

Old site URLs (`/danza_classica_accademica.html` …) are redirected (301) by `src/pages/404.astro` (rendered on demand): names that changed are mapped, the others become the same name with hyphens. CSRF: Astro's built-in origin check (`security.checkOrigin`, on by default) rejects cross-site form posts; JSON Action calls are same-origin only (no CORS headers).

### Modalità notte (light / dark theme)

One theme attribute on `<html>`: `data-tema="chiaro" | "scuro"`. `components/TemaAvvio.astro` (in the `<head>` of `Base.astro` and `Admin.astro`, also writes the `theme-color` meta) runs a blocking inline script before the first paint: saved choice (`localStorage` `inballet-tema`) or else the system `prefers-color-scheme`, so there is never a light flash. `scripts/tema.ts` keeps it in sync: follows the system while nothing is saved, other tabs (`storage`), back/forward cache (`pageshow`), updates `aria-pressed` on every `[data-tema-interruttore]` and `theme-color`, and dispatches a `tema` event on `document` (the dashboard charts recolour on it). The switch is `components/TemaInterruttore.astro` (`button` with `aria-pressed`, label «Modalità notte», moon/sun icons, CSS `components/tema.css`, hidden without scripting): an icon with a screen-reader label, after «Contattaci» in the site header (`.nav-azioni`) above 1200px, and at ≤1200px in the top bar of the mobile menu drawer, white, right of the white «Menu» label (`.mobile-menu-titolo`); tapping it there also closes the drawer, so the visitor sees the site change and in the dashboard as the «Aspetto» row of Impostazioni (a `btn-secondary` with its visible label). Changing theme reveals the new one with a circle from the button (View Transitions API, `--tema-x` / `--tema-y` / `--tema-raggio`), instant with `prefers-reduced-motion` or without the API; transitions are switched off during the change (`html.tema-cambio`). The presentation pages pass `tema={false}` to `Admin` and stay light.

Colours never depend on the theme in components: they use semantic tokens redefined in `:root[data-tema='scuro']` (`base/variables.css`, admin ones in `admin/variables.css`): `--sfondo` (white sections, page), `--superficie` (cards, dialogs, fields), `--bg-soft`, `--testo-forte` (strong text, headings), `--text-body`, `--text-muted`, `--accento` (blue text, icons, outlines: `--primary-blue-dark` on light, `--primary-blue` on dark), `--linea`, `--bordo-controllo`, `--grigio-*`, `--esito-*`, shadows, `--decoro-onde*` (half-alpha waves), `--filtro-mappa` (the «Dove trovarci» map inverted), `--filtro-logo`. `--white`, `--dark-navy`, `--primary-blue`, `--primary-blue-dark` stay fixed: use them only where the colour must not change (text on the light-blue buttons and badges is `--dark-navy`, white text on photos, `--primary-blue-dark` as a background under white text, the sponsor logo tiles stay white). Inverted badges (today in the calendar, event state) use `--testo-forte` on `--sfondo`. A new rule with a light background uses `--sfondo` / `--superficie`, never `--white`. Text on the always-dark header, mega menu, mobile menu and footer uses the fixed `--white` / `--testo-su-scuro*`, never `--grigio-*` (greys flip with the theme). The dark palette follows Material's dark theme: no pure black, brand-tinted surfaces (page `--sfondo` #111417, cards `--superficie`, alternate sections `--bg-soft` night blue), the light-blue `--primary-blue` (desaturated, ≥ 9:1 on every surface) for accents and filled buttons with dark text, no large saturated areas (the event banner turns night blue via `--banner-sfondo`), softer shadows (`--shadow-blue`) and a softer polaroid frame (`--cornice-foto`).

Images in dark mode: photos stay as they are (heroes and CTAs already have their dark veils); transparent watercolour illustrations and the Étoile avatar work on both. Light artwork has a night twin swapped by CSS on `data-tema` (the hidden one is `loading="lazy"`, so it is never downloaded): the home course cards on desktop (`grafica-corsi/<id>-scuro.webp`, `.corsi-stile-foto-notte`; the mobile `-unica` cards keep their veil) and the sponsor logos (`sponsors/<name>.png` in colour and `sponsors/<name>-scuro.png` in white, both with a transparent background and trimmed to the edge of the logo: the space around them is the tile padding, never pixels inside the file). The «Dove trovarci» map is inverted with `--filtro-mappa`, the waves use the half-alpha `decorazioni/onde-*-scuro.webp`, the CSEN mark is a roundel and works as it is; the CONI mark has a dark twin (`logo_coni-scuro.svg`: only the black Olympic ring turns white and the «CONI» lettering a light blue, swapped by CSS), with no plate behind them. A new light image (white background, pale artwork) needs its own `-scuro` twin before it goes on the site.

### Middleware (`src/middleware.ts`)

Runs on every on-demand request (pages rendered on demand, Actions, server islands, `/_image`, asset routes), never on prerendered pages:

- POST bodies over 256 KB (`Content-Length`) are refused with 413 before they are read; only the four upload Actions (`immagini.carica`, `documenti.salva`, `insegnanti.salva`, `revisione.pezzo`) accept more, and only with a logged-in session, plus `sviluppatori.scrivi` / `carica` / `immagine` with a developer session.
- POSTs to `/_actions/*` need an `Origin` header equal to the site origin (403 otherwise), so scripts and tests calling an Action must send it.
- `/_image` (the Astro endpoint that resizes the photos of on-demand pages with sharp on every request) goes through `src/lib/immagini-ottimizzate.ts`: each variant is produced once and kept in memory (64 MB, least recently used out first, `immutable` + ETag); only the shapes the site generates are accepted (`href` in `/_astro/`, `w`/`h` up to 2560, `f` webp/jpg/png, `fit=cover`), at most 90 new variants a minute. Anything else, or a new variant over that ceiling, is redirected to the original file, so photos keep showing and nobody can make the server resize without end. A new `getImage` option (quality, another format…) must be added to `PARAMETRI` / `FORMATI` there.
- Every response gets `X-Content-Type-Options`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy`; `/login`, `/dashboard` and `/area-sviluppatori` are `no-store`.

### Area sviluppatori (`/area-sviluppatori`)

The developers' own graphical editor of the whole project, so changes never need VS Code: separate password (`SVILUPPATORI_PASSWORD`, same `/login`), `noindex`, `Disallow` in robots.txt, excluded from the sitemap (`ESCLUSE` in `src/lib/sitemap.ts`), `no-store`. The client dashboard stays as limited as it is. Page `src/pages/area-sviluppatori.astro`, scripts `src/scripts/sviluppatori/`, CSS `styles/admin/sviluppatori.css` (reuses `admin/dashboard.css`: buttons, fields, toasts, `Conferma`), server code `src/lib/sviluppatori/`, Actions `sviluppatori.*`, raw files (thumbnails, downloads) from `/area-sviluppatori/file?p=` (developer session, `CSP: sandbox`).

It edits the real repository, never a copy of the data: `deposito.ts` works on the project folder in local development (`npm run dev`, Vite reloads the preview; only files touched by the area are listed and committed, `data/sviluppatori/toccati.json`) and, on Railway, on a shallow clone in the volume (`DATA_DIR/sviluppatori/repo`, `GITHUB_TOKEN` sent as an HTTP header, never stored; `git` is installed in the image). Unpublished changes are the uncommitted files of that folder; «Pubblica» makes one commit and pushes it to `main` (on Railway it first fetches and refuses only if someone else changed the same files), Railway rebuilds, and the page waits until `RAILWAY_GIT_COMMIT_SHA` equals the new commit. Every change can be discarded before publishing, and the last publications can be reverted («Annulla questa modifica» prepares a `git revert` to publish). All git work goes through one queue (`inCoda`). Paths are relative and never reach `.git`, `.env*`, `node_modules`, `dist`, `data`, `.astro`.

Every save goes through `salvaTesto()`: JSON parsed, CSS parsed (postcss), `.astro` compiled (`@astrojs/compiler-rs`), Prettier formatting with the repository's own config (Prettier is a runtime dependency for this), then the same rules as `npm run verifica:stile` (`src/lib/regole-stile.mjs`, shared with `scripts/verifica-stile.mjs`): a change that would break the build is refused with its reason (e.g. a hand-written colour outside `variables.css`).

Tabs: **Visuale** (any page, the dashboard and `/login?anteprima` in a same-origin preview at Desktop 1440 / Portatile 1280 / Tablet 768 / Telefono 390, light or dark; «Modifica» selects the clicked element, «Naviga» follows links; the panel shows the containing elements, «Testi e icone»: every text node and the `alt` / `title` / `aria-label` / `placeholder` / `content` / `href` attributes, the icon picker from the InBallet sprite, the image with «Sostituisci»; «Stile»: the source rules that hit the element, grouped as active now / hover, focus, pressed / other widths and themes, each declaration editable with live preview, token autocomplete and a colour picker (outside `variables.css` it picks the nearest token), state simulation (`[data-sv-stato]` copies of the `:hover` / `:focus` / `:active` rules), computed values and «Nuova regola» with state, width and file), **Tema** (every token of `base/variables.css` and `admin/variables.css` by group, light, dark and per breakpoint, plus the site font in `astro.config.mjs`, checked on Google Fonts), **Animazioni** (every `@keyframes` with «Riproduci» and every transition/animation declaration), **SEO** (title, description, `og:image:alt`, h1, canonical, robots and JSON-LD types of every sitemap page, editable, plus the shared SEO files), **Immagini** (every image of the repo: replace keeping format, download, delete, where used, upload), **File** (every file: CodeMirror editor loaded on demand, Ctrl+S, new, upload, rename, delete, full-text search), **Pubblica** (changes with their diff, discard, commit message, publish and live state, history with revert). The current tab and page live in the address (`#vista/percorso`), so a reload reopens them.

Texts are found in the source by `src/lib/sviluppatori/testi.ts`: the visible text is matched character by character against `src/**/*.{astro,ts,json,mjs,md}` and `astro.config.mjs`, accepting HTML entities, JS escapes, line breaks and indentation, and treating `${…}` / Astro `{…}` as computed values; only the changed stretch is rewritten, escaped for its context (markup, attribute, single/double/template string, JSON). When the same text exists in several places the area picks the one near the element's other texts on that page, otherwise asks which one (or all). Computed parts (e.g. the year from `FONDAZIONE`) and texts coming from runtime data (events, teachers, documents, Google) are reported instead of changed. CSS edits go through postcss (`stili.ts`), addressed by file, node path and selector (a changed file is detected), values checked for `;{}` and balanced parentheses. Live preview edits the matching rule of the loaded stylesheet in place (CSSOM, also when the minifier turned `max-width` into range syntax) or appends an override, and is kept while the page reloads. Covered by `tests/sviluppatori.test.mjs`.

### Backend: Astro Actions

All backend logic lives in `src/actions/index.ts` — no separate API routes. Actions are grouped: `chatbot`, `eventi`, `tipi`, `immagini`, `documenti`, `insegnanti`, `demo`, `impostazioni`, `revisione`, `sviluppatori`, `auth`. Admin actions guard themselves with `admin()` (checks session), developer actions with `sviluppatore()` (developer session, then `prepara()` of the repository). Called from the browser via `import { actions } from 'astro:actions'` or as `<form>` action.

### Data layer

Everything is JSON files on disk in `DATA_DIR` (default `./data/`, set in `.env`). The `src/lib/storage.ts` module provides:
- `readJson` / `writeJson` (atomic: write temp file → rename). `readJson` returns the fallback only when the file does not exist; any other read error is thrown, so a temporary disk error can never make a save overwrite real data with an empty list; a file that is not valid JSON is renamed `<name>.illeggibile` (kept for recovery) and the fallback is used
- `serviFile` streams uploads (ETag, 304, `Content-Length`), never loading the file in memory
- `serialized()` — a promise queue that prevents concurrent read→modify→write races

File layout in `data/`:
- `eventi.json`, `tipi_evento.json` — event data (created on first save; the repo ships no data)
- `analytics.json` — chatbot logs (capped at 10000 entries and at `GIORNI_REGISTRO` = 365 days, as the privacy policy states)
- `sessions/` — fsLite session driver
- `uploads/eventi/` — event posters: uploads are resized (1600px) and converted to WebP, plus a `<name>.mini.webp` thumbnail for the dashboard library
- `documenti.json` — hero texts and PDF list of `/documenti`, which shows the download list right under the hero with no section heading of its own (defaults in `src/data/documenti.ts` until first save)
- `uploads/documenti/` — PDFs uploaded from the dashboard, served on `/assets/documenti/<file>`
- `insegnanti.json` — header and teacher cards (name, role, bio, competenze list, photo) of the «Insegnanti» carousel in `/chi-siamo` (dashboard › Insegnanti; defaults in `src/data/insegnanti.ts`, no teachers by default: the section is hidden while the list is empty). `/chi-siamo` is therefore rendered on demand. Demo teachers (dashboard › Insegnanti › Dati demo, `generaInsegnanti` in `src/lib/demo.ts`) carry `demo: true` and are removed with their photos in one click; their portraits come from `demo/insegnanti` (vertical photos named `donna-*` / `uomo-*`, the prefix picks the name), without photos they get initials
- `uploads/insegnanti/` — teacher photos, cropped 4:5 (800x1000) and converted to WebP on upload, served on `/assets/images/insegnanti/<file>`
- `conversazioni/` — chatbot conversations, one `<uuid>.json` per chat (deleted after 30 days)
- `impostazioni.json` — dashboard settings (`revisione` on/off, Google Sheets and Drive folder addresses), see Impostazioni below
- `revisioni.json` — every proposal sent in revision mode (`leggiProposte()` in `src/lib/revisione.ts`, last 2000), saved before Google is called, with the outcome of the sheet row and of the email; downloadable as CSV from Impostazioni (`/dashboard/revisioni.csv`, logged-in only)
- `google.json` — Google Places cache (rating, review count, 5 latest reviews, opening hours), see Google below

In Docker, this directory is a named volume (`inballet-data`) so data survives rebuilds.

### Events

`src/lib/eventi.ts` is the single source: the zod schema `inputEvento` (used as the `eventi.salva` Action input; the dashboard shows its per-field errors), read/write, time rules and presentation helpers.

- Model: `data`/`ora` start and `dataFine`/`oraFine` end, all mandatory (`inputEvento` rejects an end missing or not after the start; the dashboard asks for the date, start and end time (the «Luogo», «Per chi» and «Costo» suggestions from past events come from a `datalist` whose arrow is hidden), and the end date only when «Finisce in un altro giorno» is ticked, otherwise it sends the same date and a same-day end is stored with an empty `dataFine`; demo events have both), `stato` (`pubblicato`, `bozza` = hidden from the site, `annullato`, `esaurito`), `prenotazione` link, `slug` (+ `alias` of old slugs).
- Calendar at ≤900px: event titles are hidden, each day with events shows one dot per event (up to 3) and is covered by a `.cal-tocco` button; a day with one event opens its modal, a day with several opens the day chooser `#giornoDialog` (same look as «Da dove iniziamo?» in /corsi, shared `components/scelta.css`: date, «N eventi: scegli quale vedere», one row per event with state, time and place), and picking one opens that event's modal. Above 900px titles are shown (two lines at most). The calendar opens on the month of the next event.
- No per-event pages on purpose: the `/spettacoli-eventi` section has no visible header (only an `sr-only` h2) and opens on the month calendar (month name centred between the two arrows), with the «Calendario / Elenco» switch above it (the SSR list stays as the view without JavaScript, `@media (scripting: none)`); details open in a modal (SSR list + `scripts/calendario.ts`), same structure at every width: the sticky top bar holds «Condividi» as an icon-only `btn-icon` (the label is `sr-only`; the icon turns into a check for 2.5s when the link is copied) next to the close X, both white with a soft shadow in this modal because they sit on the light-blue header; a `--bg-soft` header (`.evento-testata`, flipped site wave `--onda-svg` as its bottom edge) with type/state labels, title and description; the poster as a white-bordered «polaroid» rotated 3° (straightens on hover, opens whole and enlarged on click; it sits on a blurred copy of itself, `contain`); then Quando / Dove / Per chi / Costo (label above value, two columns above 600px with a 3rem gap and a grey `--linea` vertical rule centred in it beside every right-hand cell, stopping 1rem short of the horizontal rules; one column below) and «Prenota» and «Aggiungi al calendario» (two underlined text links with the Google and Apple brand icons, side by side at every width). Desktop (>900px, 52rem with a poster, 48rem without): the 10rem poster sits on the right inside the header, vertically centred on labels, title and description (same top and bottom offsets as the header text), so it no longer crosses the wave; tablet and mobile: the poster is centred under the header, straddling the wavy edge. Demo posters are always vertical. `?evento=<slug>` (or an old slug / the id) opens the modal and sets og:title/og:image to that event, so shared links preview the poster. The page also carries schema.org/Event JSON-LD for upcoming non-demo events (`datiStrutturati()`).
- Text fields are stored as plain text and escaped when rendered; the description is clean HTML from `testoRicco(…, true)`.
- One rule for "past" everywhere (site, banner, dashboard, chatbot): `passato()` = `fineEvento()` is over, Rome time: an event ending at 12:10 is «Evento concluso» from 12:10:01, whatever its start. Between `inizioEvento()` and the end `inCorso()` is true: «In corso» on the cards, the modal and the dashboard. Events saved before the end became mandatory fall back to the start time (23:59 without any time) until they are edited.
- Event banner (`Banner.astro`, server island, `no-store`): the not-past events ordered by `fineEvento()`, so each one gets its turn before it ends; it stays up until the end (from the start its date reads «In corso • fino a …») and the page switches to the next one at the exact second (timer, re-checked on `visibilitychange` / `pageshow`). It receives the 10 events ending first plus every other event on their days, so a day group is always complete. When other shown events start on the same day as the current one, the banner shows them together: «N eventi in programma», «<day> • dalle <first start>» (or «in corso» once one has started), and «Scopri di più» opens `/spettacoli-eventi`, not a single event. Closing it (or «Scopri di più») hides only that event, or every event of that day group (`banner_dismissed_<id>` in localStorage): the next event shows again to everyone.
- Demo posters (`creaLocandina` in `src/lib/demo.ts`) are always vertical, 1080×1350 (4:5).
- Removing a type keeps it on the events that use it; deleting a poster clears it from the events that use it.

### Google (reviews and opening hours)

`src/lib/google.ts` is the only place that talks to Google: one Places API (New) Place Details call (`rating,userRatingCount,reviews,regularOpeningHours`, billed once as Enterprise + Atmosphere) every 30 days, from the server with `GOOGLE_PLACES_API_KEY`, saved in `data/google.json`. Every visitor sees that file; nothing Google runs in the browser (no Maps JS, no client key). An expired file is still served while the refresh runs in the background; a failed refresh is retried after 1, 2, 4… hours (24 at most), and an answer without reviews or without opening hours is refreshed after a day instead of 30, so Google is called at most about once a day in the worst case. Concurrent visitors share one read of the file and one call; a `google.json` with the wrong shape is ignored. No hand-written fallback: the opening hours exist only on Google (Google Business Profile is the place to change them, the site follows within 30 days or at once if `google.json` is deleted).

- Home «Dicono di noi»: `<RecensioniGoogle server:defer>` (static page, the island is rendered on demand, `Cache-Control` 1h); `scripts/recensioni.ts` (`<recensioni-google>` custom element) only drives the carousel and «Leggi tutto».
- `/contatti` «Orari segreteria»: `<OrariSegreteria server:defer>` with the week and the openingHoursSpecification JSON-LD of `#scuola`; `scripts/orari.ts` (`<orari-segreteria>`) marks today and «Aperto/Chiuso ora» in the visitor's browser (Rome time).
- The same data feed `riepilogoScuola()` (opening hours and rating for `/llms.txt` and the chatbot).

### Impostazioni e modalità revisione

The dashboard is kept simple on purpose: the top bar holds only the logo, the four sections (Eventi, Chatbot, Documenti, Insegnanti; a second row at ≤860px) and one gear button (`.topbar-impostazioni`, icon only, `aria-label`). Sections have no visible title (the underlined tab already says where you are; the h1 is `sr-only`, no counts or subtitles): each one starts with its actions on the left (`.pagina-azioni`), the main one first (`btn-primary`, «Nuovo evento»…) and then an eye button (`.btn-icona`, `fa-eye`) that opens the matching public page in a new tab. List rows open the edit dialog themselves (the whole row is the button, with an `sr-only` «Modifica»): no pencil icons, only the row-specific actions (view on the site, reorder, delete). Things changed rarely sit in closed panels under the list (`<details class="pannello pannello-apribile">`, chevron on the right): «Testi della pagina» in Documenti, «Titolo e testo della sezione» in Insegnanti, «Dettagli tecnici» in Chatbot (cache, response time, fallbacks, provider chain and checks). Chatbot shows only three numbers (Messaggi, Persone, Spesa stimata), the 7/30/90-day pills, the two charts, the frequent questions and the latest conversations. Forms never write «obbligatorio» next to labels (required fields carry `required` and are named in the error); the event dialog puts Data, Inizio and Fine on one row (`.campi-3`, date on its own row ≤640px) and shows «Data di fine» only with «Finisce in un altro giorno». Events are filtered only by «In programma» / «Passati» plus the search. Everything else lives in «Impostazioni» (`components/dashboard/ImpostazioniModal.astro`, `scripts/dashboard/impostazioni.ts`): a wide modal (`.modal--impostazioni`) with one row per setting, description on the left and control on the right (`.imp-riga`, stacked ≤640px), in this order: «Aspetto» (night mode), «Il sito» (opens it in a new tab), «Dati demo» (only on Eventi, Insegnanti and Chatbot: opens that section's `DemoModal`, closing Impostazioni), «Modalità revisione» with a switch (`.interruttore`, `role="switch"`) that reveals the Google Sheets and Drive folder addresses side by side, «Elimina tutto» (opens the existing `EliminaTuttoModal`); the footer has «Esci dalla dashboard» on the left (`form="formEsci"`, a logout form outside the settings form) and «Annulla» / «Salva», closing without saving restores the saved values (`src/lib/impostazioni.ts`, saved in `data/impostazioni.json`). Saving with revision on calls the Google script, which creates the «Revisione» tab of the sheet if missing. The columns are decided by the site (`COLONNE` in `src/lib/revisione.ts`: Data · Pagina · Sezione del testo · Testo · Sezione di immagini e video · Immagini e video · Inserito, the last a checkbox for the developers to tick once the change is on the site) and sent with every call: the script adds any missing column in place (existing rows shift with it), so changing the columns never needs the script deployed again.

While revision is on, a logged-in admin sees on every public page a still dark-blue frame around the window (`--revisione` = `--primary-blue-dark` in both themes, so it shows on white, light-blue and dark sections; `--revisione-bordo` thick, rounded inner corners, `.revisione-cornice`) and, glued to its bottom edge, the «Revisione» tab (`.revisione-apri`: pen icon and label in white, `--revisione-linguetta` high, centred on the bottom of the browser, concave fillets joining it to the frame; on hover only the tab itself darkens, the fillets keep the frame colour). Frame and tab sit above everything, chatbot included: while revision is on (`html.revisione-attiva`) the chatbot button rises above the tab at ≤600px and the chat panel stops above it. The dialog has no heading (its accessible name is «Revisione · <page>»), only the two blocks and «Invia» centred under them, and never scrolls on a computer: the text box height follows the window (`clamp(6rem, 100dvh - 31rem, 14rem)`), down to about 620px of window height. On phones the dialog fills the screen, the file picker is a «Scegli foto o video» button (the native input is hidden) and «Invia» stays stuck to the bottom. It opens a wide dialog (`scripts/revisione.ts`, CSS `components/revisione.css`, built in JS) with two separate light-blue blocks side by side (stacked ≤900px): «Testo» (new text, then «Sezione» and the optional «Punto preciso» side by side) and «Immagini o video» («Sezione» + «Punto preciso», then several files at once, 50 MB each at most, `MAX_FILE_REVISIONE`). The section list is read from the page itself (`main > section`, numbered, with its h1/h2), plus «Nuova sezione» and «Altro punto»; a section is mandatory for the part that is filled. After sending, the dialog closes and a notice above the tab (a rounded card on `--superficie` with a dark-blue border and dark text, not a pill) says what went («Testo inviato», «Immagini inviate», «Testo e video inviati»…) for about 2 seconds; errors stay inside the dialog. Visitors never load it: login, the dashboard and saving the settings set the readable cookie `inballet-revisione=1` (24h, `segnaRevisione()`; logout and revision off remove it), and `scripts/revisione-avvio.ts` (in `Base.astro`) imports the widget only when that cookie is there and the page is not inside a frame (so the presentation shows it only where a step asks for it with `?revisione`); every Action still checks the session. Files never touch the site: each one goes to Google Drive in a resumable upload, the browser sends 8 MB pieces to `revisione.pezzo` and the server forwards them to the Drive session (low memory), inside a subfolder named after the page; then `revisione.invia` first saves the proposal in `data/revisioni.json`, and only then, in parallel, appends one row to the sheet (date, page name linked to the page address, the two sections, text, the file names linked to Drive) and emails it (`src/lib/email.ts`, nodemailer over `SMTP_URL`) to the addresses of the «Email che ricevono ogni proposta» field in Impostazioni; the proposal counts as sent once it is saved on the site, and each copy records whether the sheet and the email went through. Files themselves exist only on Drive (an upload that fails shows its error in the dialog), the email carries their Drive links.

Google is reached only through the Apps Script web app `google/revisione.gs`, run as the owner of the sheet and folder (a personal Drive cannot receive files from a service account). Setup once: script.google.com › new project › paste the file › Project settings › Script properties `CHIAVE` = a long random string › Deploy › New deployment › Web app, Execute as «Me», Who has access «Anyone» › authorise › copy the `/exec` URL into `GOOGLE_REVISIONE_URL` and the same key into `GOOGLE_REVISIONE_CHIAVE`. The owner account must be able to edit the sheet and the folder. After editing `google/revisione.gs`, deploy a new version of the same deployment (Manage deployments › edit › New version: the URL stays). Every answer of the script carries `versione` (`VERSIONE` in the script, `VERSIONE_SCRIPT` in `src/lib/revisione.ts`): when they differ the site says the script must be deployed again instead of failing with a technical error, so raise both together whenever the script changes. The server accepts upload sessions only on `https://www.googleapis.com/`.

### Chatbot (Étoile)

`src/lib/chatbot/`, one file per concern; `index.ts` (`rispondi()`) runs the flow: sanitize → in-memory rate limit per IP hash (1s, 6/min, 30/h, 100/day; 60 attempts/h block the IP for an hour, and a blocked IP is no longer logged; IPv6 addresses count by /64 network, `reteDi()`) → insult/spam filter → site-wide ceilings (`tetto` in `protezioni.ts`, whatever the IP: 60 messages/min, 600/h, 3000/day, then a «riprova tra qualche minuto» answer without reading or writing anything; 300 refused messages logged per hour, so a flood cannot push the real history out of `analytics.json`) → conversation memory (last 6 exchanges, max 20 per chat) → response cache (first message of a chat only, in memory, 24h, key includes the knowledge version, which includes the date; identical first messages arriving together share one model call) → daily spend cap → model ceilings (20 calls/min, 200/h, 1000/day and 6 at the same time: with the spend cap this bounds the bill even if every request comes from a different address) → provider chain → log + save exchange. No FAQ fallback on purpose (the owner finds it far worse than the AI): when the cap is hit or no provider answers, Étoile says it cannot answer right now and gives the school's phone, WhatsApp and email (logged as `offline`, not saved in the conversation).

- `fornitori.ts`: provider chain from `CHATBOT_MODELLI` (`fornitore:modello,...`, in priority order). Two adapters: official `@anthropic-ai/sdk` for Claude, OpenAI-compatible chat completions for gemini/mistral/groq/openrouter/openai/cerebras/`compatibile` (any URL in `CHATBOT_COMPATIBILE_URL`). Providers without a key are skipped. Hedged requests: a provider that fails hands over at once, one still silent after 5s gets the next one started in parallel, first valid answer wins and the others are aborted (the beaten one counts an error). Per-provider timeout 12s; 502/503/529 retried once at the end of the queue; circuit breaker (3 errors or slow losses → 5 min pause, 429 → `retry-after`, 4xx config errors → 30 min). No streaming (speed is bound by the provider queue).
- Opening the chat calls `actions.chatbot.prepara` (crawl + index build), so the first question doesn't wait for it. Crawl and index build are shared by concurrent requests; a failed or half-empty crawl (under half of the pages read before, or over 45 s) keeps the previous texts and is retried after a minute.
- `conoscenza.ts`: about 4k input tokens per question instead of the whole site (~21k, which hit the Gemini free-tier tokens-per-minute limit after ~10 questions a minute). System prompt, cached by the providers (Claude: 1h on the fixed part): fixed part = instructions + official data (`riepilogoScuola({ conFaq: false })`, shared with `/llms.txt`) + index of the site pages (path: title); variable part = date, documents, next 10 events (rebuilt every 5 min). Then `contesto()` adds to the last user message only the passages relevant to that question («PASSAGGI DEL SITO»), chosen among page sections, every FAQ and the next 30 events (demo ones included because the site shows them). Follow-ups ("e da che età?") search with the previous questions too and favour the pages cited in the last answer.
- `ricerca.ts`: local BM25 search, no external service, no vector DB: Italian normalisation (accents, light stemming incl. verbs), stop words, `SINONIMI` in `src/data/chatbot.ts` (replacements applied before stop words: «bimba» → bambina bambini, «dove» → sede indirizzo…), ages indexed by range («da 6 a 8 anni» answers «7 anni»), section titles and page path weighted double, max 6 passages / 5500 characters / 3 per page. `dividi()` cuts a page at its `##` headings (max 1200 characters, short sections merged). Covered by `tests/ricerca.test.mjs`.
- `pagine.ts`: the server crawls its own site (from `/`, following internal links, max 150 pages; first `localhost:$PORT`, then the request origin) and keeps the `<main>` text of each page, dropping lines repeated on many pages and every `section[data-chatbot-escludi]` (event calendar, «Corsi simili», gallery, contact CTA, home FAQ: already indexed from the data). Re-read every 30 min in production (1 min in dev) in the background. Any new page linked from the site is covered automatically; text outside `<main>` (navbar, footer) and server islands are not, contacts and opening hours come from the official data.
- `registro.ts`: `analytics.json` entries with provider, tokens, cost (`PREZZI` in `src/data/chatbot.ts`), latency, fallbacks; written in batches (one write every 2s at most, capped at `MAX_LOG`). For the daily spend cap a model missing from `PREZZI` counts at the most expensive listed price (it used to count zero, which switched the cap off): add new models to `PREZZI`.
- `formato.ts`: escape everything, then rebuild bold/lists/links; links only to site paths, tel/mailto and a few known hosts.
- Dashboard (Chatbot tab): spend, provider chain status, quality check (`VERIFICHE` in `src/data/chatbot.ts`, run per provider via `actions.chatbot.verifica`), last conversations.

### UI system (use it, don't invent new styles)

The mobile menu never scrolls with all accordions closed: its full-width decoration below «Contattaci» flexes into the remaining height, with compact spacing on short screens. ### CSS structure (`src/styles/`)

No `<style>` blocks and no `style=` with real properties in `.astro` files: all CSS lives in `src/styles/`, and the file that uses it imports it in its frontmatter (`import '../styles/pages/chi-siamo.css'`), so each page loads only its own CSS. Plain CSS (no scoping): class names must be unique across files, prefix them with the page or component.

```
styles/
  global.css        only an ordered @import list of the shared modules (imported by layouts/Base.astro)
  base/             variables.css (ALL tokens: palette, type scale, radii, shadows, motion, header and wave sizes,
                    decorative image paths) · reset.css (reset, html/body, focus, skip link) · typography.css
  layout/           container, intro-editoriale, decori (decoro-onde + veils), onde (wavy edges)

                    (navbar incl. the fixed header, footer, banner, chatbot, galleria, insegnanti-*, corsi-simili, …)
  pages/            one file per page, imported by the page; only layout (grid, spacing, alignment), never its own
                    label/title/button typography or colours
  admin/            dashboard and login (own tokens in admin/variables.css, not loaded by the public site)

```

New values (colours, sizes, shadows) go in `base/variables.css`; a rule needed by two or more pages goes in `components/` or `layout/`, not copied. `npm run verifica:stile` enforces this.

## Type scale and single style system
One system, all in `src/styles/` (tokens in `base/variables.css`, headings and text in `base/typography.css`); pages and components only lay things out. Run `npm run verifica:stile` before pushing (rules in `src/lib/regole-stile.mjs`, also enforced by the developer area): it fails on a `<style>` block in an `.astro` file, a literal `font-size` / `font-weight`, a hand-written colour, an inline style with real properties, or a heading restyled outside `base/typography.css`.

- **Roles, not sizes**: pages never pick a size, weight, line-height or colour for text. `base/variables.css` ("Ruoli tipografici") defines each role and `base/typography.css` applies it: titles `--h1-*` … `--h4-*` (h1 56px, h2 46, h3 32, h4 26 on desktop; one style per level on every page), body text `--body-*` (22px, 1.7, one colour for every paragraph/list), small text `--small-*` (`<small class="testo-piccolo">`: ages, frequencies, file sizes, sources; never on a `<p>`), hero lead (`.hero-lead`: body size, light weight), label `--label-*` (`.eyebrow`/`.titoletto`), buttons/links `--ui-*`, numbers `--numero-*`. Changing a role in the variables file changes the whole site. The raw scale `--text-5xl` … `--text-2xs` feeds the roles and sizes icons/numerals. **Every `<p>` is body text at `--body-size` (22px desktop, fluid down to 18px)**, on the site, in the chat panel and in the dashboard; anything smaller is not a paragraph (`<small>`, labels, UI). Dashboard/login (`admin/`, which imports `base/variables.css`) and the chat panel use the same palette, font and raw scale, never their own sizes or hex colours.
- **Tags carry the role**: titles are `h1`-`h4` (card/course/document/sede names `h3`, titles under an `h3` `h4`), text is `<p>` (or `li`, `dd`…), labels `<p class="eyebrow">`. Never a `<span>`/`<div>` for a title or a paragraph: `span` only for an inline fragment inside text (e.g. `sede-tag`, a count-up number) or an icon wrapper inside a button. Don't wrap button/link labels in a span; the visual «Scopri il corso →» label inside a whole-card link is `<span class="link-cta">`, timeline years are `<span class="voce-anno numero-medio">`, fine print (copyright, captions, notes) is `<small>`. `h2`/`.titolo-sezione` section title, dialog `h2` uses the `h3` style, `.valore` = `h4` style on a non-title (phone, email). Components never set size/weight/line-height/letter-spacing/colour on titles or paragraphs; big numbers `.numero-grande` / `.numero-medio`.
- **Labels**: one uppercase label style, `.titoletto` (and `.eyebrow`, same look plus margin): menu group titles, categories, table headers, footer column titles, any h2/h3 that is only a label.
- **Hero lead** under the h1: `.hero-lead` (home and inner pages), body size on desktop and `--lead-size-mobile` (16px) at ≤768px.
- **Buttons**: `.btn-primary`, `.btn-secondary`, `.link-cta`; round icon buttons `.btn-icon` + `--chiudi` (the close X of every dialog, site and lightbox: light grey circle `--grigio-100`, black X, `--grigio-300` on hover; the dashboard `.modal-close` matches it), `--scuro` (on photos/dark), `--contorno` (carousel arrows), `--nudo` (menu). 44px hit area, role-sized glyphs: close 18px, menu 28px, other commands 24px. Direct icon children inherit the button role; close icons explicitly use `--icona-chiudi`. The navbar "Contattaci" is a `btn-primary` (`aria-current="page"` turns it white).
- **Motion**: durations and easing only from the tokens `--durata-breve` (hover colours), `--durata` (small movements, dialogs, dropdowns), `--durata-pannello` (mobile drawer), `--durata-lenta` (hero video fade), `--curva` (or `--curva-morbida` for the symmetric map motion). Animate only `transform` and `opacity` (colours on hover); layout properties are animated only for the scroll-shrinking header (80 → 64px; `body::before` in `base/reset.css` paints `--header-dark` over the body's top padding, so while the header grows back on the way up no white step shows under it), the accordions (the mobile footer columns in `scripts/footer.ts` with the Web Animations API on the `<details>` height, `--durata-pannello`, so they open and close smoothly in every browser) and the width of the review dots (old and new pill change together, so the row keeps its width). The only load animation is the hero text rising in (`sale`, children of `.hero-content` / `.chisiamo-hero-glass` with an 80 ms cascade), starting from opacity 0.001 so the text still counts for LCP at first paint. Infinite animations only where they say something and only while visible: the light streak running along the Chi siamo timeline (`timeline-scia` on the desktop serpentine, `timeline-flusso` on the mobile line, the rings breathing around the «Oggi» dot and the «Dove trovarci» map pins and the streak running along the pin-to-photo lines (shared keyframes `respiro` with `--respiro-da` / `--respiro-a` and `scia` with `--scia` in `components/movimento.css`), and the second blob breathing around the «Cosa impareranno» icons, `impara-respiro`; both run only under the `in-vista` class that `scripts/in-vista.ts` toggles on every `[data-in-vista]` element); the event banner pulse runs 3 times. `prefers-reduced-motion` is handled once in `base/reset.css`; scripts check it only for JS-driven motion (carousels, counters, hero video). Carousels run their frame loop only while visible; the hero video starts after `load`. Scroll motion is CSS only (`components/movimento.css`, `animation-timeline: view()`, inside `prefers-reduced-motion: no-preference` and `@supports`, longhand properties because the minifier would fold `animation-timeline` into an invalid shorthand): section headers and list items rise in (`rivela`, `--rivela-y`) with a per-column cascade, framed photos enter with `scena`, the ondine drift with the scroll (`ondina-flusso` in `components/ondina.css`, the only paint-based motion). Never on the first section (hero) and inactive inside horizontal scrollers. Micro-interactions: arrows in buttons and `link-cta` move on hover, buttons press in (`:active`), course card photos zoom slowly, the home figures lift on hover.
- **Icons** use shared size roles at every breakpoint: `--icona-editoriale` (48px), `--icona-editoriale-compatta` (36px), `--icona-in-testo` (at least 24px), `--icona-mini` (20px, also `--icona-link` for text action arrows), `--icona-comando` (24px), `--icona-chiudi` (18px), `--icona-menu` (28px). Small icon indicators use `--icona-punto`; the opening-status ring uses `--icona-stato` (14px). The generated base applies the inline minimum to icons without a component role. Never use literal font sizes in components.
- **Rounded lines and cards**: no square line ends or corners anywhere. A CSS `border` always has square ends, so separators are never `border-top/bottom/left/right`: they are drawn by `components/linee.css` as 2px (`--linea-sp`) lines with round caps, using the element's own background (`--lc: <colour>; background: var(--linea-basso)`, also `--linea-alto` / `--linea-sx` / `--linea-dx`, several separated by a comma; set `--ls` for a thicker bar; on an element that also needs a background colour, put `background-color` after). The «+» of accordions is `background: var(--piu)` (`--ps` = size). Separators of a list sit only between its items, never before the first or after the last: put the line on `li:not(:last-child)` (or `li + li`), not on the list itself, and drop it from the first row of a grid (`.righe`, `.documenti-lista`, `.faq-item`, `.oltre-elemento`, `.corso-meta-card`, `.evento-dettagli`, the footer columns and the mobile menu follow this). Pseudo-element lines (`::before` / `::after`) get `border-radius: var(--radius-pill)`; short rules between groups are the double wave `components/ondina.css`. Boxes (cards, grids of cells, dialogs) always have `border-radius: var(--radius-card)` (or `--radius-md` for small ones); a grid of cells separated by a 1px `gap` on a coloured background is not allowed, use separate rounded cards with a gap or lines on the cells. Full-screen mobile dialogs and the mobile menu drawer are the only square boxes.
- **Colours** only from the palette tokens (theme-aware ones first, see «Modalità notte»: `--sfondo`, `--superficie`, `--testo-forte`, `--accento`, `--bordo-controllo`): `--white`, `--dark-navy`, `--primary-blue*`, `--text-*`, greys `--grigio-*`, states `--esito-*`, lines: ONE hairline colour `--linea` for every separator on light backgrounds (same as the home accordion; never invent another), `--linea-su-scuro` on dark, text on dark `--testo-su-scuro*`, and for transparencies `rgb(var(--navy-rgb) / .4)` (also `--bianco-rgb`, `--nero-rgb`, `--scuro-rgb`, `--blu-rgb`, `--blu-scuro-rgb`, `--header-rgb`).
- **Font weights** only from the tokens `--font-light` … `--font-bold` (300-700) or the role tokens (`--heading-weight`, `--ui-weight`…). Text colours from the role tokens (`--body-color`, `--small-color`, `--heading-color`, `--label-color`, and the `*-su-scuro` variants for dark sections) or `--text-body` / `--text-muted`.
- **Inline `style=`** is left only for the image data computed at build time, as CSS variables (`--sfondo-*` / `--fuoco-*` from `sfondo()` and `<Img fuoco>`); the rules that use them are in `components/sfondo.css`. Counters and per-item tweaks (index, number of items, logo scale, veil) are CSS: `:nth-child`, `:has()`, modifier classes or data attributes. The few `element.style` writes in `src/scripts` are runtime values (measured heights, drag offset, carousel slide state).

## Pagina Corsi (/corsi)
The hero carries a «Scegli il corso» button that opens a dialog with one link per `categorieCorsi` entry (`scripts/trova-corso.ts`; plain links in `<noscript>`). Then one section per category (`corsi-stile`, alternating white with `decoro-onde` / `corsi-stile--soft`): `intro-editoriale` header (eyebrow «N corsi», h2 with the last word in `<em>`, `descrizione` with `enfatizza`) and the courses as `<ElencoPercorsi>` of `<SchedaPercorso>` photo cards (photos in `src/data/immagini-sottocorsi.ts`): three fixed columns on desktop in every category (3 + 1 when there are four), all cards the same size, horizontal scroll with arrow buttons on mobile (`scripts/corsi.ts`). Then the closing «Non sai quale corso scegliere?» block. The photo cards (`components/schede-percorso.css`, also used by «Corsi simili» and the home «La danza oltre i corsi» on phones) are spaced by `--scheda-gap-x` / `--scheda-gap-y` (3rem / 4rem desktop, 2.5rem / 3.25rem ≤900px), with the separator lines centred in the gap; in the phone scroller every card flows on its own (no shared rows), so the text always sits right under its title. The home «La danza oltre i corsi» scroller is the exception: every title there is written on two lines (`righe` in `vociOltre` of `index.astro`, rendered by `<SchedaPercorso righe>` with a `<br>`) and its cards share their rows (subgrid, in `pages/index.css`), so title, text and arrow sit at the same height on every card; a new entry needs its own two `righe`. The home «Un corso per ogni età» cards are four columns from 1280px (two below) and each `sintesi` in `categorieCorsi` stays within about 65 characters so all four read on three lines there. A new course only needs to be listed in its category in scuola.ts plus a photo in immagini-sottocorsi.ts.

## Corsi simili
Every course page (`[corso].astro`) shows `src/components/CorsiSimili.astro` right after "Gli obiettivi": the other courses of the same `categorieCorsi` entry (scuola.ts), current course excluded; age label and frequency come from the course's own data in corsi.json. Desktop: at most 3 cards per row (6-column grid, cards span 2, an incomplete last row is centred); tablet 2 per row; mobile the shared photo cards. A new course only needs to be listed in a category to appear there.
